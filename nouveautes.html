vim, pour de bon, et les épreuves à la main

  • vim (et vi) s’ouvre pour de bon, dans le terminal : l’invite devient le mode (« : » en normal, « -- INSERTION -- »). i, a ou o pour écrire, Échap pour arrêter, :w pour enregistrer, :wq, :x ou ZZ pour enregistrer et sortir, :q! pour fuir.
  • :q sur un tampon modifié : E37. Un fichier de root sans sudo : E45 (sudo vim, alors). exit, quit, Ctrl+C : « Tapez :qa! puis Entrée ». Au cinquième essai raté, Stack Overflow vient à la rescousse (2,7 millions de vues).
  • defi montre maintenant trois épreuves à la main, une fois chacune, récompensées tout de suite : réparer soi-même un incident en moins d’une minute, shipper un vendredi sans avoir lancé Xfce de la session, sortir de vim.
  • Deux succès Steam : Sorti de vim (sans redémarrer le PC), et À la main (les trois épreuves).

Les scripts et cron : la maintenance, planifiée

  • Les scripts : une commande par ligne (tubes compris), # pour commenter, set -e pour s’arrêter à la première erreur, exit pour finir, sleep pour attendre. ./script.sh demande chmod +x ; bash script.sh, non.
  • cron : crontab -e (dans nano, avec un modèle commenté), crontab -l, crontab -r, crontab fichier, … | crontab -. Les champs classiques (*/10, 1-4, mon-fri) et @hourly, @daily, @reboot. La sortie des tâches arrive par courrier, regroupée si on ne lit pas ; MAILTO="" pour s’en passer.
  • Les ships partent déjà tout seuls : cron fait la maintenance. Une tâche qui lance la bonne commande (certbot renew, journalctl --vacuum-size=1G, systemctl restart pgbouncer…) évite l’incident qui va avec pendant deux heures, et répare celui qui est en cours.
  • Les commandes de root vont dans sudo crontab -e : dans la crontab de dev, sudo n’a pas de terminal pour demander le mot de passe (le courrier du cron le dit). Planifier git revert HEAD protège le DNS, mais défait le travail des agents à chaque passage.
  • Les tâches ne tournent que machine allumée : une tâche à 3 h du matin ne tourne que si le jeu est ouvert à 3 h. Un succès Steam : Maintenance préventive.
« Avant, la maintenance tombait le vendredi à 17 h. Maintenant, elle tombe toutes les heures. Personne ne l’a vu venir : c’est le principe. »l’agent, 14 h 46

  • man : la page de manuel, avec NOM, SYNOPSIS, OPTIONS, BOGUES (connus, assumés) et VOIR AUSSI. Pour les commandes sans page écrite, la description vient de l’aide du jeu : man et help ne peuvent pas se contredire.

L’historique, le vrai : !!, sudo !!, Ctrl+R ; cp et mv

  • history : les commandes numérotées (history 5, history -c pour effacer ; history | grep marche).
  • !! relance la dernière commande, !n la n-ième, !-2 l’avant-dernière, !mot la dernière qui commence par mot. Comme zsh, le terminal affiche la ligne développée avant de la lancer.
  • Et le classique sudo !! : la commande refusée, relancée avec sudo. Un succès Steam : Le mot magique.
  • Ctrl+R cherche dans l’historique, comme bash et zsh : on tape un bout de commande, Ctrl+R encore pour une plus ancienne, Entrée la lance, une flèche la garde pour l’éditer, Échap annule.
  • cp et mv dans le terminal : dans un dossier ou vers un nouveau nom, -r pour un dossier, sudo chez root, l’espace disque compté. Déplacer /bin fait planter le système, comme dans Thunar.
« sudo !!, c’est demander poliment après avoir essayé de force. Exactement comme les agents, mais dans l’autre sens. »l’agent, 14 h 36

Le shell, le vrai : tubes, redirections, grep

  • Des tubes : ls | grep, journalctl -u api | grep -i error | tail, fortune | cowsay. Dans un tube, ls donne un nom par ligne, comme le vrai ; les erreurs restent à l’écran, comme stderr.
  • Des redirections : > fichier, >> fichier, < fichier, 2>/dev/null, 2>&1. Écrire chez root sans droits : « permission non accordée », car la redirection appartient au shell, pas à sudo. D’où … | sudo tee.
  • Des enchaînements : ;, && et || (un grep qui ne trouve rien compte comme un échec).
  • Les outils : grep (-i, -v, -n, -c, -o, -r, -w, -l), head, tail, wc, sort (-r, -n, -u, -k), uniq (-c, -d, -u), find (-name, -type, -maxdepth), less, tee. Tab complète la commande après un tube. Un programme qui veut l’écran (htop, nano) ne passe pas dans un tube.
  • L’aide montre ls à la place de dir (qui marche toujours, comme le dir de coreutils). Un succès Steam : Plombier, trois tubes dans une seule commande.
« Avant, les agents écrivaient des logs que personne ne lisait. Maintenant, on peut les filtrer avant de ne pas les lire. »l’agent, 13 h 42
