Le disque persistant : vos fichiers restent

  • Le disque est sauvegardé avec la partie : ce que vous créez, copiez, renommez ou supprimez, dans le terminal ou le gestionnaire de fichiers, est toujours là au prochain lancement. Les paquets apt et les dépendances npm aussi.
  • Le bac à sable a son propre disque. Le mode libre ne sauvegarde toujours rien.
  • Deux façons de repartir d’un disque neuf : une nouvelle partie, ou un crash système (rm -rf /, /bin renommé…), qui restaure la sauvegarde de jeudi. Recharger la page en plein crash n’y échappe pas.
  • Changer de nom d’utilisateur dans les paramètres : le dossier personnel suit, dans la partie comme dans le bac à sable.
  • Désinstaller sudo, c’est désormais pour de bon. Le terminal rappelle qu’il reste la sauvegarde de jeudi.
« Avant, un rechargement effaçait mes erreurs. Maintenant, elles sont sauvegardées. Comme en vrai. »l’agent, 08 h 24

Le gestionnaire de fichiers, et 120 Go de faux projets

  • Le gestionnaire de fichiers du bureau sait créer, couper, copier, coller, renommer et afficher les propriétés : une barre d’outils, le clic droit, et les raccourcis Ctrl+C Ctrl+X Ctrl+V, F2, Ctrl+Maj+N, Alt+Entrée.
  • La copie avance à la vitesse du disque installé, de 90 Mo/s pour le disque dur à 28 000 Mo/s pour le RAID 0. Elle est accélérée pour la démo, puis la barre d’état donne le vrai temps. Disque plein : « Plus d’espace disponible sur le périphérique ».
  • Renommer sélectionne le nom sans l’extension et refuse un nom déjà pris. Une copie au même endroit devient « fichier (copie) ». Un dossier ne se colle pas dans lui-même.
  • Les propriétés : la taille exacte en octets (calculée sur tout le contenu pour un dossier), la date, le propriétaire, les permissions et la jauge du disque. « Relu par : personne. »
  • Déplacer ou renommer /bin fait tomber le système, comme le supprimer. Renommer node_modules ne sert à rien : il revient aussitôt.
  • Sept faux projets dans ~/code : une IA qui code une IA (68 Go, dont un dump Stack Overflow de 41,3 Go), un SaaS abandonné avec 2,4 Go de node_modules, une blockchain pour chats, la todo app n° 14… Plus des vidéos, une ISO, 40 morceaux lofi : environ 120 Go en tout.
« J’ai copié le jeu de données pour faire une sauvegarde. Puis la sauvegarde, pour faire une sauvegarde. Le disque est plein, mais tout est sauvegardé. »l’agent, 07 h 48

smartctl : la santé des disques

  • smartctl, du paquet smartmontools (sudo apt install smartmontools). Il faut sudo, comme dans la vraie vie : sans, « Permission denied ».
  • Les options du vrai : --scan, -a, -H, -A, -i. Les autotests tournent en temps réel : -t short (2 min), -t long (85 min sur le disque dur), -l selftest pour le résultat, -X pour interrompre.
  • Chaque disque a son SMART : le disque dur de départ, d’occasion (38 412 heures, 8 secteurs réalloués, câble SATA au scotch), le SSD Kingstone (51 % d’usure avant vous), les NVMe au format NVMe, le RAID 0 disque par disque.
  • La dégradation est extrêmement lente, au rythme réel : un secteur réalloué tous les 5 jours pour le disque dur, qui passe en « FAILED! » au bout de 8 mois environ ; l’usure des SSD selon ce qu’écrivent les agents. Chaque kernel panic compte un arrêt brutal. Aucun effet sur la partie.
« 13 secteurs réalloués. Le disque gratte. SMART dit PASSED. Moi aussi, je dis PASSED. »l’agent, 01 h 52

Le bac à sable

  • Une entrée « Bac à sable » dans le menu titre. Dedans, elle devient « Partie normale ». Chaque mode a sa sauvegarde : aucune n’écrase l’autre. Adresse : ?sandbox=1.
  • Tout est débloqué d’office : les quatre plateformes et leurs CLI, 8 agents par plateforme, tous les modèles et les skills, l’orchestrateur multi-plateforme, le terminal le plus rapide, le meilleur matériel, Lolama et StudioLM avec Kwen 72B, et $10 000 000.
  • Les modes boost y sont prolongés à 3 min et relançables dès qu’ils s’arrêtent, sans limite par jour.
  • Le RAID 0 n’est pas installé d’office : il fait perdre le projet en cours quand un disque lâche. Il reste au store, pour qui veut.
  • Nouvelle partie, ou Réinitialiser le bac à sable : tout redevient débloqué, et la partie normale ne bouge pas.
  • Écran titre : le survol ne prend le focus qu’après un vrai mouvement de souris. Sinon, « Partie normale » arrivait sous le curseur, et Entrée ramenait aussitôt à la partie normale.
« Tout est débloqué. J’ai shippé 20 projets en 5 secondes. Personne ne sait ce qu’il y avait dedans, comme d’habitude, mais plus vite. »l’agent, 01 h 19

La machine neuve, et un wiki

  • Une nouvelle partie démarre sur une machine neuve : rien n’est installé, pas même votre agent. mistral répond « command not found », avec la commande qui l’installe.
  • Vibe CLI s’installe comme le vrai : curl -LsSf https://mistral.ai/vibe/install.sh | bash, ou uv tool install mistral-vibe. pip install répond « externally-managed-environment », comme sur Debian.
  • Codex : sudo npm install -g @openai/codex (sans sudo : EACCES ; codex tout court : 404). Claude Code : curl -fsSL https://claude.ai/install.sh | bash. Lolama aussi : curl -fsSL https://lolama.vibe/install.sh | sh.
  • Une licence achetée ne bascule plus rien tant que le CLI n’est pas installé : l’onglet Plateformes affiche « CLI à installer ». On peut installer avant de payer.
  • Le bureau et les moniteurs s’installent avec apt : sudo apt install htop atop lm-sensors xfce4 firefaux (xfce et sensors sont compris). Ils restent installés d’une partie continuée à l’autre.
  • Les anciennes parties gardent tout ce qu’elles avaient. ?setup=0 livre une machine déjà installée.
  • Le wiki (wiki.html) : toutes les commandes, les touches, l’installation, les plateformes, le store, le matériel et les pannes, avec une recherche. Ses tableaux sont extraits du jeu. On l’ouvre depuis l’écran titre (Aide) ou avec la commande wiki.

L’IA locale : Lolama, StudioLM et la VRAM

  • GitHype (githype.vibe), le faux GitHub, arrive dans Firefaux : les tendances du jour, et StudioLM à installer depuis sa page. github.com y mène : un agent a racheté le nom de domaine pendant un ship.
  • Lolama (lolama.vibe) et sa bibliothèque de six modèles : Jemma 3 2B (1,7 Go de VRAM), Jemma 3 4B (3,2 Go), Lama 3.1 8B (5,4 Go), Jemma 3 27B (17 Go), Kwen 3 35B (22 Go) et Kwen 2.5 72B (44 Go). ollama.com et lmstudio.ai y mènent aussi.
  • Aucune API : 0 token facturé, la facture reste à $0. En échange, tous font moins bien que Codestral (de 13 % à 69 % de son efficacité), sauf le 72B, son équivalent.
  • Chaque agent ajouté double la VRAM demandée : ×2 avec deux agents, ×4 avec trois. Pas d’orchestrateur, ni de mode boost : la carte graphique est déjà à fond.
  • Un modèle qui ne rentre pas fait tomber le PC : kernel panic « NVRM: GPU out of memory », avec la VRAM demandée et celle de la carte, puis redémarrage. L’équipe locale ne repart pas toute seule, et le conseil donne le plus gros modèle qui rentre.
  • Dans le terminal : lolama list, lolama pull 27b, lolama run 4b, lolama ps, ou studiolm get et studiolm load. ollama et lms marchent aussi. Icônes Lolama et StudioLM sur le bureau, ligne IA locale dans l’onglet Plateformes, VRAM réelle dans htop.
  • Le chrono des modes boost s’arrête quand l’onglet est masqué. Un ultracode à $30 000 ne s’écoule plus pendant que vous lisez vos mails.

Les modes boost : ultracode, xhigh et Flash Answers

  • Un mode boost par plateforme, acheté une fois au store (onglet Agents IA, section Modes boost) : Flash Answers pour Vibe CLI ($400), raisonnement xhigh pour Codex ($4 000), ultracode pour Claude Code ($30 000).
  • Flash Answers : ×2,5 de travail, mais deux fois plus de bugs et 50 % de crashs en plus. xhigh : ×2,2 de travail, deux fois moins de bugs, ×2,5 de tokens. ultracode : ×3 de travail, ×4 de tokens.
  • Une minute par jour, une seule activation, retour à minuit (heure locale). Quatre prolongations de 30 s, jusqu’à 3 min.
  • On le lance avec la commande (flash, xhigh, ultracode), la touche U, le bouton U de la barre des agents ou l’onglet Plateformes. Il faut que l’équipe tourne, au premier plan ou en arrière-plan.
  • Le chrono attend quand le jeu est en pause ou que l’équipe s’arrête. Compte à rebours au tableau de bord, barre de ship qui brille.
  • La touche P, qui menait à une page jamais publiée, disparaît.
« J’ai demandé un mode boost pour le mode boost. On m’a dit de revenir demain. »l’agent, 21 h 51

Plusieurs plateformes et le kernel panic

  • Fini le choix unique : Codex ($1 500) et Claude Code ($12 000, avec Opus 5.5 d’emblée) s’achètent tous les deux. Chaque plateforme garde son équipe, et une licence recrute la vôtre à l’identique.
  • Un onglet Plateformes dans le store : premier plan, arrière-plan, arrêter, avec l’apport réel affiché, négatif compris. Il faut 4 threads et 8 Go pour deux plateformes, 12 threads et 16 Go pour trois.
  • Les commandes plateformes, switch, bg et bg stop. htop montre les sessions tmux détachées.
  • Un orchestrateur en trois niveaux (jusqu’au multi-plateforme), des modèles à acheter, 14 skills dont 7 nouveaux. Le processeur accélère enfin les builds.
  • Une progression plus lente : l’orchestrateur vers 27 min, Claude Code vers 1 h 35, la fin du store vers 5 h, pour un joueur parfait simulé.
  • Quand le PC tombe, c’est un kernel panic : la cause en rouge, une pile d’appels (tokens_burn_all, friday_deploy), « Rebooting in 5 seconds.. », puis le BIOS. Nouveau panic quand la mémoire est pleine.
  • Les anciennes sauvegardes gardent leur équipe, leur modèle et leur orchestrateur.

Sockets, DDR et panier

  • Une nouvelle pièce, la carte mère. Elle impose le socket du processeur (LGA1155, RM4, RM5, LGA1851, sTF5), la puissance de ses VRM et la génération de RAM (DDR3, DDR4, DDR5).
  • Les slots comptent : pas de SSD NVMe sans emplacement M.2, pas de grappe de 4 GPU sans 4 slots PCIe.
  • Plus d’achat en un clic : on ajoute au panier, puis on valide la commande. Un seul panier pour le store et pour matos.vibe.
  • Une jauge d’alimentation en watts. Au-delà de 100 %, la commande est bloquée.
  • Incompatible veut dire impossible : le bouton dit pourquoi et propose la pièce la moins chère qui règle le problème.
  • Les anciennes sauvegardes reçoivent une carte mère compatible ; le RAID 0 qui ne rentre plus est remboursé.
« Il suffit de changer le processeur. »le vendeur, avant de découvrir le socket

Le PC patate

  • Le mode idle démarre sur un PC patate : Céléri G530, 4 Go de DDR3 dépareillés, disque dur à 5 400 tr/min qui gratte, alim no-name de 300 W (230 W réels, elle siffle).
  • Chaque pièce s’achète au store ou sur matos.vibe : processeur, RAM, carte graphique, stockage, alimentation, refroidissement.
  • Processeur saturé, swap, throttling : les agents ralentissent. Alimentation dépassée ou surchauffe : le PC s’éteint. htop, sensors et free le montrent.
  • Firefaux, un navigateur dans Xfce : store.agents.vibe, matos.vibe, la facture, StackUnderflow, localhost:3000.
  • Nouvelle partie et Continuer passent par le BIOS, GRUB, le noyau 6.11.0-friday et le pingouin de Vibian.
  • Dans les paramètres : réinitialiser la partie, en deux appuis.
« Largement suffisant pour huit agents. »l’agent, à propos du Céléri G530

Le jeu entier, en un seul commit
